1. Data Augmentation & Vocabulary Extraction

To fine-tune a model that speaks Hindi *exclusively* using a restricted vocabulary of 300 words, we start by programmatically compiling a structured training set. A set of 65 core seed questions is expanded through combinatorial templates (Locations, Pronouns, Description, etc.) to generate 516 dialogue pairs.

Every assistant response is stripped of punctuation and tokenized to extract unique Hindi words. These unique words are combined with a padding pool of standard connectors and verbs to compile a file called hindi_vocab.json containing exactly 300 unique words.

Gemma's Chat Template

Supervised Fine-Tuning requires dialogues to be wrapped in the base model's structural template. Gemma uses custom turn markers: 

<start_of_turn>user
नमस्ते दोस्त! आप कैसे हैं?<end_of_turn>
<start_of_turn>model
मैं ठीक हूँ। आप कैसे हैं?<end_of_turn>

These structural tags (like user, model, and turn bounds) tell the autoregressive network when the prompt ends and when it is expected to generate tokens.

2. QLoRA: Quantization & Memory Optimization

Gemma 2B has 2.6 billion parameters. Loading them in standard 16-bit float (FP16) requires ~5.2GB of VRAM. QLoRA (Quantized Low-Rank Adaptation) quantizes these base weights to 4-bit, dropping VRAM footprint to ~1.5GB.

Quantization Bit-Reduction Comparison

FP16 (16-bit Float)
16 bits / weight

VRAM Footprint: ~5.2 GB

→
NF4 (4-bit NormalFloat4)
4 bits / weight

VRAM Footprint: ~1.5 GB

Mathematical Concepts of QLoRA:

  • NormalFloat4 (NF4) Data Type: W is scaled so that its weights follow a normal distribution. NF4 splits the normal distribution into 16 discrete intervals with equal expectation values, optimizing dynamic range representation compared to standard integer quantization.
  • Double Quantization (DQ): Quantization scales are themselves quantized (from 32-bit float to 8-bit float), saving an extra 0.37 bits per parameter.
  • Compute Dequantization: During the active forward and backward passes, the 4-bit weights are dynamically dequantized to 16-bit bfloat16 for calculations. No computation actually takes place in 4-bit; it is strictly a storage compression technique.

Memory Scaling Equations

A weight matrix W is quantized into integers q using a quantization scale factor c:

q = round( W / c )

To run a forward pass multiplication with input activation x, we dequantize q dynamically:

Y = ( q × c ) × x

By keeping the base weights frozen in 4-bit NF4, we eliminate the need to track optimizer states for these parameters, which typically consume twice as much memory as the weights themselves.

3. LoRA: Low-Rank Adaptation

Instead of training all 2.6 billion weights, LoRA freezes the base weight matrix Wbase and decomposes the weight update matrix ΔW into two slender matrices, A and B, joined by a bottleneck dimension called rank r.

LoRA Matrix Decomposition

Wbase (Frozen) d × k
+
A d × r
B r × k

LoRA Forward Pass Equation

The forward pass computation in a LoRA-equipped layer is mathematically defined as:

h = Wbase · x + ΔW · x
h = Wbase · x + ( α / r ) · ( B · A ) · x
  • Input x is passed through both the frozen base weight and the bottleneck adapters.
  • Scaling factor α/r ensures that when the rank r is changed, the relative magnitude of the adapter's adjustments remains stable without needing to reset the learning rate.
  • Gradient Updates: Backpropagation only calculates derivatives and updates weights for matrices A and B, keeping memory footprints low.

Cosine Learning Rate Decay

During training, the learning rate starts at 2 × 10-4 and is decayed according to a cosine schedule. This allows the model to make large structural updates in the early epochs and fine-tune subtle updates as training finishes, ensuring stable convergence.

8-bit Paged Optimizer

Using paged_adamw_8bit reduces the memory occupied by AdamW optimizer states. It compresses state parameters to 8-bit, and dynamically "pages" them to CPU RAM if GPU memory limits are reached, preventing Out-Of-Memory training crashes.

Logits Masking Simulator

The logits processor intercepts raw model prediction scores (logits) before the softmax selection step and applies a mask.

Output Probabilities Equation

Masked logits are converted to selection probabilities using Softmax:

P(tokeni) = elogitsmasked(i) / ∑j elogitsmasked(j)

When a disallowed token's logit is set to -∞, its term e-∞ becomes exactly 0, making its probability 0.00%.
